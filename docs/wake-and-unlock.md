# 软件亮屏与系统解锁

产品目标是关闭显示器、允许后台工作继续，软件不应擅自点亮屏幕；用户主动唤醒后，密码和指纹解锁必须正常。屏幕唤醒与启动目标应用是两件事：只有用户配置的指定按键才打开其应用或项目。任何额外防护都应默认关闭，由用户了解影响后开启。

## 已发现的问题

旧版防护用 `SIGSTOP` 冻结整个电脑操作服务，又要求显示器已亮、会话已解锁、退出自动熄屏模式后才恢复。冻结不会关闭已有的辅助功能、屏幕采集和进程通信连接。服务仍被系统视为存活，却无法回复请求；如果登录流程等待该服务响应，就与“解锁完成才恢复”形成相互等待。该设计不具备解锁兼容性，2.5.2 已撤下。

现场记录显示：服务被冻结之后，Touch ID 已匹配成功，但未观察到对应的解锁完成；同一故障过程里，WindowServer 记录一个被暂停的服务没有回应已取走的 ping。用户强制重启后，撤下机制并反馈可以正常解锁。这是有力的关联证据，不能冒充完整的系统死锁堆栈：重启前没有取得卡住的 loginwindow 堆栈，而且该第三方服务在未冻结时也发生过独立崩溃。

独立、无界面的进程通信实验验证了一个有限结论：冻结服务端时，已有连接保持打开，已发出的请求没有回复；恢复进程后才收到回复，正常退出则让对端读到连接关闭。这只是机制验证，不能证明当时具体哪个 macOS 调用卡住。生产代码不据此改用强退服务，也不自动重启屏幕记录。

另一个已从轻醒源码与回归测试确认的问题是：锁屏期间仅隐藏提示，仍执行 20 秒后的 `pmset displaysleepnow`。初始倒计时和后续重试也有同样问题。2.5.3 将这些请求限制为已解锁的当前控制台会话；会话在最后一次检查时变为锁定，也撤销关屏。解锁完成后才建立新的桌面期限，已取消的模式保持取消。这修正了轻醒自己的打断行为，不证明第三方服务的卡死原因已经完全定位。

## 为什么不能承诺拦截任何软件

Apple 的公开接口 `IOPMAssertionDeclareUserActivity` 会请求点亮显示器，且普通进程即可调用。它不等于真实键盘或鼠标输入。因此，收到显示器已唤醒的通知或“用户活动”电源声明，不能可靠判断是用户本人，还是软件提出的请求。[Apple 文档](https://developer.apple.com/documentation/iokit/1557127-iopmassertiondeclareuseractivity)

检查过的公开 IOKit 和 AppKit 接口中，没有供普通应用在所有其他进程的显示器唤醒请求生效前逐个否决的统一回调。这个结论基于当前接口审查，不声称所有系统版本的内部实现都相同。

Apple 开源的 powerd 包含按声明类型统一禁用的内部管理路径，要求管理员身份；它没有按“真实用户 / 普通软件”区分的参数，不能直接作为符合本产品目标的开关。[Apple PowerManagement 源码](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmconfigd/PMAssertions.c)

收到唤醒通知后立即再次关屏属于事后处理，屏幕可能已经亮过，也可能打断验证；仅凭没有捕获到按键判断“软件唤醒”，在锁屏、指纹验证和输入权限不足时并不可靠。因此当前版本不实现这种替代方案，也不把通用防软件唤醒标为已完成。

## 可用机制和后续约束

当前修复方向已收窄为 **Codex 请求入口**：在原生操作请求发出前检查桌面状态，并在关闭显示器时避免重新拉起服务。针对本机安装版本的候选补丁和无界面测试见 [Codex 请求入口保护](../integrations/codex-request-guard/README.md)。候选代码已验证拒绝路径及原授权结果的传递，尚未集成到正式签名的 Codex 安装包，不能标为已启用。

当前保留的机制是在桌面操作发出前检查轻醒模式、显示器和会话状态，遇到关屏或锁屏就延后该次桌面请求，继续代码、构建及网络等后台工作。它需要调用方配合，并保留原有授权检查；无法覆盖绕过包装器直接调用系统的应用。虚拟浏览器可承接网页检查，不能代替真实 macOS 锁屏或原生应用解锁验收。

后续若增加防护，必须有可验证的调用方协作接口或受支持的系统接口。不得冻结、终止系统解锁依赖，不得以反复关屏代替拦截，不得自动解锁或恢复屏幕记录；不迁移旧版同意为新方案的开启授权。必须分别验证软件请求、键盘、鼠标、映射键、慢速密码输入和 Touch ID；无法识别的情况优先交给系统处理。

## 本轮验证边界

回归用例在旧实现中能触发锁屏关屏请求，修正后覆盖 5 秒和 20 秒到期、长时间验证、旧重试、动作边界突然锁定、正常解锁后的完整期限以及退出模式。控制器测试替换实际关屏动作，未唤醒显示器、操作密码界面或测试真实指纹。真实硬件行为仍以用户观察为准。
