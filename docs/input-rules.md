# 按键规则与调用接口 v1

一条规则对应一个明确的输入和一个目标：**指定按键 → 屏幕动作 → 应用及可选项目文件夹**。普通唤醒通知只用于屏幕状态判断，不打开目标。新建规则默认停用；用户保存并启用后才执行。

## 在应用里配置

打开“轻醒设置 → 按键规则”，从顶部选择已有规则，或选择“＋ 新建规则”。

| 输入类型 | 如何指定按键 |
| --- | --- |
| 键盘快捷键 | 点击“录制按键”，在设置窗口按下所需组合键。修饰键属于匹配条件；不同组合可对应不同目标。 |
| 鼠标按键 | 点击“录制按键”，在设置窗口按下左键、右键、中键或侧键，也可以带修饰键。 |
| 外部映射按键 | 在轻醒保存规则，复制这条规则的映射命令，再由手柄、快捷指令等工具把具体按键绑定到该命令。每条规则的命令不同。 |

每条规则都可选择应用，并附带一个项目文件夹。只选择应用时启动或唤回该应用；同时选择文件夹时，通过 macOS 的打开文档接口把文件夹交给该应用。Codex 使用随应用附带的官方 `codex app [PATH]` 工具打开工作目录，避免把目录当成普通文档而未选中项目。只选文件夹时使用系统默认方式打开。其他应用需支持通过 macOS 接收文件夹；这不等同于切换到应用内部的某个任务 ID。

“亮屏并打开目标”可限制为只在熄屏、锁屏或自动熄屏模式下执行。“切换屏幕”在正常使用时进入熄屏倒计时，恢复亮屏时才执行此规则的目标。系统要求密码时，轻醒先亮屏并取消自动熄屏，保留这次按键指定的目标；用户正常解锁、桌面稳定后再打开应用及所选项目，不需要再按一次键。等待期间不会自动解锁或反复请求亮屏。

等待解锁时再次触发有效规则，只保留最近一次的目标。编辑、停用、删除该规则，或重新启动自动熄屏，会取消原先等待的目标。普通亮屏或解锁没有对应的待执行按键规则时，不打开应用。

同一个键盘组合或鼠标组合最多启用一条规则。选择的按键仍会传给原应用，轻醒不屏蔽其原有作用。建议选择不会影响日常输入的组合。停用或删除规则可停止对应动作。

## 输入监控

只有启用键盘或鼠标规则后才安装监听器，登录时自动恢复这些已启用的规则。保存规则不会主动弹出输入监控授权；用户需要点击“授权输入监控”，在 macOS 设置中允许“轻醒按键”，再回到轻醒保存规则。未授权时不会监听，也不会尝试绕过权限。

监听器只比较按键码、鼠标按钮和修饰键，不保存文字或输入历史。锁屏、安全输入以及系统保留按键可能影响事件投递，需要在具体设备上验证。监听器保留唤醒前约一秒的显示器状态，以识别先唤醒屏幕、随后才送达的指定按键；仍要求有匹配的按键事件，不因唤醒本身启动目标。

映射入口由外部工具主动调用，不需要轻醒监听所有按键。Joy-Con 的按钮编号和映射由手柄项目维护；轻醒设置会只读显示当前 Karabiner 配置中使用旧入口的按键，例如 HOME（button13）。

## 稳定接口

接口 v1 使用规则 ID 关联调用与目标，规则改名或更换应用 / 项目时保持 ID 不变。调用方无需随设置变化修改源码。

```text
lightwake://trigger/<规则 ID>
```

设置中的“复制此规则的映射命令”会生成可直接使用的命令，例如：

```sh
open -g 'lightwake://trigger/00000000-0000-0000-0000-000000000001'
```

示例 ID 仅演示格式，实际使用应从应用复制。调用仅接受已保存、已启用且类型为“外部映射按键”的规则；其他输入类型、未知 ID、查询参数、片段或其他路径均不执行动作。目标应用和文件夹只从本机规则读取，调用地址不能附带 shell 命令或任意打开目标。

现有应用身份继续保持：

| 标识 | 作用 |
| --- | --- |
| `local.xy.screen-guard-control` | 接收规则地址，以及旧版打开应用的兼容调用。 |
| `local.xy.turn-off-display` | 启动原有自动熄屏流程。 |
| `local.xy.turn-on-display` | 退出自动熄屏并保持亮屏；不执行其他按键规则的目标。 |
| `local.xy.lightwake-settings` | 打开设置。 |

把本次构建的应用一起复制到“应用程序”，使 Launch Services 注册接口。更新应用后，已有调用地址和规则 ID 保持有效。

## 旧 HOME 入口

已有的 `open_application` → `轻醒按键.app` 调用对应固定 ID `legacy-toggle`。有规则配置时，只执行该 ID 的启用映射规则；停用、删除或改成其他输入类型后不执行。完全没有配置文件的旧式调用保留基本屏幕切换，不默认打开 Codex 或其他应用。

本机迁移可以把已有的 HOME → Codex 行为保存成这条规则，之后用户在应用里调整目标。新安装不自动生成用户专属 HOME 映射。普通键盘或鼠标唤醒不经过这个兼容入口。

## 存储与后台启动

```text
~/Library/Application Support/ScreenGuard/input-rules.json
~/Library/Application Support/ScreenGuard/input-rules-status.json
~/Library/LaunchAgents/local.xy.lightwake.input-rules.plist
```

配置版本为 1，原子写入；冲突、损坏或未知版本不执行规则。应用标识不能指向轻醒自身，避免递归调用。移除最后一条启用的键盘 / 鼠标规则后，会移除其登录监听任务。

监听任务必须启动支持 `ScreenInputRulesVersion = 1` 的新“轻醒按键.app”，并使用 `--listen`。启动只安装监听，不执行默认切换；缺少新版辅助应用时，设置会报错并保留原配置。

此任务与默认关闭的 Codex 防亮屏保护相互独立。启用按键规则不会开启防亮屏保护或屏幕历史记录。

## 验证

自动检查覆盖输入精确匹配、规则各自的目标、应用与项目组合、重复输入和禁用 / 删除行为、调用地址校验、首次不安装监听、旧辅助应用拒绝、登录启动不执行屏幕动作以及设置布局。解锁回归覆盖锁屏不打开目标、稳定解锁后自动执行一次、会话不可用或重新锁定时继续等待、目标替换与取消、异步启动顺序，以及普通解锁不执行目标。测试使用临时目录和替换的动作，不启动真实监听器、不请求权限、不实际唤醒显示器。

真实验收需用户手动启用并授权后，分别用选中的键盘、鼠标和映射按键测试熄屏前后、锁屏 / 解锁、普通唤醒和不同目标应用。构建和模拟检查不能证明某个物理按键在锁屏状态下必定可用。
