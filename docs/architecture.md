# 架构说明

LightWake 的源码位于 `apps/screen-guard`，负责自动熄屏、唤醒后的倒计时，以及恢复正常使用。

## 屏幕工具

同一份 AppKit 程序按各自 `Info.plist` 中的 `ScreenGuardRole` 选择入口，包括关闭屏幕、开启屏幕、按键调用和设置。

| 文件 | 职责 |
| --- | --- |
| `GuardState.swift` | 纯状态机，接收单调时钟时间与屏幕睡眠 / 唤醒事件，输出提示、数字倒计时、熄屏等阶段。 |
| `ScreenGuard.swift` | 控制器、提示窗口、收起动画、菜单栏入口、电源声明和系统事件监听。 |
| `ControlStore.swift` | 用模式令牌和跨进程文件锁协调开启 / 关闭操作。 |
| `Main.swift` | 应用角色的启动与重复打开行为。 |
| `ScreenButtonState.swift` | 按键的状态选择：正常亮屏启动倒计时，倒计时 / 熄屏 / 锁屏选择保持亮屏。 |
| `ScreenButtonController.swift` | 协调取消令牌、唤醒及执行对应规则的应用 / 文件夹目标。 |
| `ScreenInputRules.swift` | 版本化的按键规则、冲突校验和映射调用协议；只读识别现有 Karabiner 入口。 |
| `ScreenInputRuntime.swift` | 用户启用后监听指定键盘 / 鼠标按键；监听器安装、权限请求与退出。 |
| `InputRulesSettingsView.swift` | 选择 / 录制按键、配置各自目标、保存和删除规则。 |
| `QuietProtectionSettings.swift` | 默认关闭的设置开关、开启前的副作用提示和状态显示。 |
| `QuietProtection.swift` | 读取用户选择；确认后才安装资源和 LaunchAgent，关闭时请求安全清理。 |
| `resources/quiet-desktop/` | 随设置应用打包的状态检查、任务调用包装器和进程防护程序。 |

### 计时与取消

双击“关闭屏幕”启动 5 秒窗口：前 3 秒显示提示，随后平移缩小到每块屏幕可见区域的左上角，余下 2 秒显示数字。动画不会额外增加总时长。

收到真实的 `screensDidSleepNotification` 后，下一次 `screensDidWakeNotification` 会启动新的 20 秒窗口。前 3 秒显示提醒，随后 17 秒显示角落数字；轮询、重复唤醒通知不会重置起点。计时使用 `systemUptime`，避免系统日期变化影响倒计时。

密码界面的显示器唤醒与成功解锁分别处理。锁屏期间仍按 20 秒期限处理意外亮屏，但隐藏桌面提示；确认会话从锁定恢复到桌面时，废弃旧期限，重新开始完整的 3 秒提醒和 17 秒角落倒计时。重复的解锁或唤醒通知不会续时。已通过“开启屏幕”取消的模式也不会因解锁而恢复。

控制器监听锁定、解锁和会话切换通知，并在每次计时、显示器事件及最终关屏调用前读取 `CGSessionCopyCurrentDictionary`。这让过期定时器即使先于解锁通知送达，也能识别新的会话状态；最终检查在模式文件锁内完成。用户不在当前控制台或无法读取会话时暂停关屏操作，恢复桌面后再开始完整 20 秒。锁屏字段 `CGSSessionScreenIsLocked` 及 `com.apple.screenIsLocked` / `com.apple.screenIsUnlocked` 通知是当前 macOS 的未公开约定，系统升级后需验证。生命周期日志仅记录会话和显示器状态，不记录密码或模式令牌。

控制器在主线程处理计时与动作。到期通过 `/usr/bin/pmset displaysleepnow` 请求显示器睡眠；在尚未收到睡眠通知时，状态机会间隔 20 秒重试，不因延迟的计时回调连续发出命令。

运行中的关闭工具持有 `PreventUserIdleSystemSleep` 电源声明，允许显示器关闭，同时阻止闲置触发整机睡眠。停止时释放声明；这不改变系统持久电源设置，也不替代系统的锁屏策略。

“开启屏幕”先将本机模式文件写为 `off`，再发送分布式停止通知，并以短时 `caffeinate -u` 请求亮屏。模式令牌是最终依据：关闭工具会在每次执行前检查令牌，并通过同一把 `flock` 将最后一次检查和实际关屏命令串行化。取消写入完成后，旧令牌不能再触发关屏。运行状态位于当前用户的 `Application Support/ScreenGuard` 目录。

提示是独立的 AppKit 非激活窗口，忽略鼠标点击，避免夺取当前应用焦点；角落数字是桌面窗口，不是菜单栏倒计时。系统锁屏界面不属于这些窗口的显示范围。

### 屏幕切换调用入口

`controller` 角色构建为 `轻醒按键.app`，采用后台应用策略。具体手柄和 Karabiner 映射由独立的手柄项目维护，映射可打开对应规则的地址；旧版打开此应用的调用仍有兼容入口。

控制器同时检查模式文件和“关闭屏幕”进程，避免遗留令牌被误判为活动倒计时。切换规则在正常亮屏时后台打开“关闭屏幕”；恢复亮屏时，先在原有文件锁下写入 `off`、发出停止通知并执行短时 `caffeinate -u`，随后在后台打开“开启屏幕”，再执行触发规则自己的应用 / 文件夹目标。普通屏幕唤醒通知不调用目标启动逻辑。锁屏身份验证仍由系统处理。应用启动期间的后续规则串行处理；同一规则短于 180 毫秒的重复事件合并，后续排队请求保留对应规则的目标。

监听器只在用户启用键盘或鼠标规则后安装，登录时使用 `--listen` 启动，不执行屏幕切换。它使用经过系统授权的只读事件监听，不吞掉按键、不保存输入历史。映射规则使用 `lightwake://trigger/<规则 ID>`，仅接受已保存并启用的映射类型规则；不接受附带的命令或目标参数。详细约定见 [按键规则与调用接口](input-rules.md)。

## 打包

`build_local.py` 使用当前 Xcode 的 Swift 编译器构建同一份程序，配合角色配置生成“关闭屏幕.app”“开启屏幕.app”“轻醒按键.app”和“轻醒设置.app”。设置应用包含防亮屏资源。构建过程不安装、启动防护或写入用户选择。`MakeIcons.swift` 绘制两款图标：深蓝色显示器与月亮用于关闭屏幕、按键调用及设置，绿色显示器与电源符号用于开启屏幕。构建不依赖已经安装的应用。

应用包采用本机临时签名，用于自行构建和本机安装；当前流程不包含 Developer ID 公证或 App Store 分发。

## 验证范围

根目录的 `scripts/test.py` 汇总计时状态、模式存储和控制器集成检查。集成检查通过可替换的时钟、提示和关屏动作验证行为，不实际执行关屏。`--visual` 额外运行真实提示窗口和动画检查。

防亮屏检查覆盖首次使用保持关闭、取消确认无副作用、不同用户目录安装、失败回滚及关闭后的恢复。进程信号测试只操作临时编译的独立测试进程，不连接真正的 Codex 电脑操作服务。设置布局检查不显示窗口。详细设计见 [防亮屏保护](quiet-protection.md)。

这些检查覆盖代码路径，不能代替不同 macOS 版本、硬件和多显示器环境中的实际安装验证。`scripts/build.py` 构建屏幕应用和设置，并检查生成应用的签名。

解锁回归验收：启用自动熄屏，等系统要求密码后唤醒并解锁。桌面应直接显示新的 20 秒提醒，3 秒后显示角落数字 17；解锁前消耗的时间不得导致桌面提前关屏。再次测试重复唤醒通知及锁屏期间取消模式，确认它们不会延长计时或重启已取消的模式。
